## 项目结构
渠道管理涉及路由、控制器、服务、模型、DTO、转接器与配置等模块，整体分层清晰：
- 路由层：对外暴露渠道管理的HTTP接口
- 控制层：请求校验、权限与业务编排
- 服务层：渠道选择、负载均衡、故障转移、配额与计费
- 模型与DTO：持久化结构与传输对象
- 转接层：适配不同AI提供商的协议与数据结构
- 配置层：全局与运行时配置

## 架构总览
渠道管理在请求进入后，经过路由分发到控制器，再由服务层进行渠道选择与调度，最终通过转接器调用具体AI提供商。关键流程如下：

```mermaid
sequenceDiagram
participant C as "客户端"
participant R as "路由层"
participant Ctrl as "控制器"
participant Svc as "服务层"
participant Sel as "渠道选择"
participant Ad as "转接器"
participant Prov as "AI提供商"
C->>R : "HTTP 请求"
R->>Ctrl : "分发到渠道控制器"
Ctrl->>Svc : "执行渠道操作(创建/更新/选择)"
Svc->>Sel : "根据策略选择渠道"
Sel-->>Svc : "返回目标渠道"
Svc->>Ad : "构造请求并调用"
Ad->>Prov : "转发至具体提供商"
Prov-->>Ad : "返回响应/错误"
Ad-->>Svc : "标准化结果"
Svc-->>Ctrl : "业务结果"
Ctrl-->>C : "HTTP 响应"
```

### 服务层：渠道选择、负载均衡与故障转移
- 渠道选择策略
  - 权重轮询、随机、最少连接、延迟优先、亲和性绑定
- 负载均衡
  - 基于权重与实时健康状态的动态分配
- 故障转移
  - 失败重试、降级到备用渠道、熔断与退避
- 配额与计费联动
  - 额度扣减、用量统计、价格计算

```mermaid
flowchart TD
Enter(["进入选择"]) --> Load["加载可用渠道"]
Load --> Strategy{"选择策略"}
Strategy --> |权重轮询| Weighted["按权重分配"]
Strategy --> |随机| Random["随机选择"]
Strategy --> |最少连接| MinConn["选择最少连接数"]
Strategy --> |延迟优先| Latency["选择最低延迟"]
Strategy --> |亲和性| Affinity["按用户/会话亲和"]
Weighted --> Health["健康检查"]
Random --> Health
MinConn --> Health
Latency --> Health
Affinity --> Health
Health --> Ok{"健康?"}
Ok --> |是| Select["选定渠道"]
Ok --> |否| Fallback["触发故障转移"]
Fallback --> Retry["重试或降级"]
Retry --> Select
Select --> Exit(["返回渠道"])
```

## 故障排查指南
- 常见错误
  - 鉴权失败：检查密钥、鉴权头、令牌有效期
  - 超时与连接失败：检查网络、代理、超时配置

- 诊断步骤
  - 查看渠道健康状态与日志
  - 使用测试接口验证连通性
