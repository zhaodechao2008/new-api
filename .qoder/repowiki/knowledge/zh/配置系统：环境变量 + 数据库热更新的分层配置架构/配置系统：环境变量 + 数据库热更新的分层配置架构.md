New API 的配置文件系统采用「启动时环境变量/命令行参数 + 运行时数据库持久化 + 内存 OptionMap」三层叠加模式，支持热更新与多模块分层管理。

**1. 加载顺序与优先级**
- 进程入口 `main.go` 通过 `godotenv.Load(".env")` 加载 `.env` 文件（失败仅 debug 日志），随后调用 `common.InitEnv()` 解析所有环境变量与 `-port`、`-log-dir`、`-version`、`-help` 等命令行 flag。
- `common/init.go` 中通过 `GetEnvOrDefault` / `GetEnvOrDefaultBool` / `GetEnvOrDefaultString` 三个工具函数统一读取环境变量并赋予默认值，写入 `common` 包全局变量及 `constant` 包中的运行时常量。
- 应用启动后由 `model.InitOptionMap()` 将内存中的默认配置全部写入 `common.OptionMap`，再调用 `loadOptionsFromDatabase()` 从数据库 `options` 表覆盖同名 key，实现「环境变量 < 数据库配置」的优先级。
- 运行期间通过 `SyncOptions(frequency)` 定时拉取数据库变更，经 `updateOptionMap` 实时刷新内存，无需重启生效。

**2. 分层配置管理器（ConfigManager）**
- `setting/config/config.go` 提供 `ConfigManager`，以 `name.key` 扁平键名注册任意结构体配置，通过反射自动序列化/反序列化为 JSON 字符串存入数据库。
- 各子模块在 `setting/` 下按功能域拆分：`operation_setting`（运营）、`system_setting`（系统安全/OIDC/Passkey）、`model_setting`（模型定价）、`ratio_setting`（计费比率）、`performance_setting`、`console_setting`、`billing_setting` 等，每个子目录包含对应的 struct 定义与 JSON 编解码方法。
- `model/handleConfigUpdate` 根据 key 前缀路由到对应 ConfigManager 实例，并在特定模块（如 `performance_setting`、`tool_price_setting`、`billing_setting`）触发缓存失效或索引重建。

**3. 运行时配置访问**
- 传统配置项集中在 `common.OptionMap`（`map[string]string`，带 RWMutex），由 `InitOptionMap` 初始化后通过 `UpdateOption` / `UpdateOptionsBulk` 原子更新。
- 新式分层配置通过 `config.GlobalConfig.Get(name)` 获取已注册的 struct 指针，直接读写字段即可，避免硬编码 switch-case。
- 前端通过 `/api/option` 接口读取 `OptionMap` 暴露的配置，实现前后端配置同步。

**4. 关键环境变量（部分示例）**
- 基础：`PORT`、`DEBUG`、`SESSION_SECRET`、`CRYPTO_SECRET`、`NODE_TYPE`、`VERSION`
- 数据库：`SQL_DSN`、`LOG_SQL_DSN`、`SQLITE_PATH`、`SQL_MAX_IDLE_CONNS`、`SQL_MAX_OPEN_CONNS`、`SQL_MAX_LIFETIME`
- 缓存：`REDIS_CONN_STRING`、`SYNC_FREQUENCY`、`MEMORY_CACHE_ENABLED`、`CHANNEL_UPDATE_FREQUENCY`、`BATCH_UPDATE_ENABLED`、`BATCH_UPDATE_INTERVAL`
- Relay：`RELAY_TIMEOUT`、`RELAY_IDLE_CONN_TIMEOUT`、`RELAY_MAX_IDLE_CONNS`、`RELAY_MAX_IDLE_CONNS_PER_HOST`
- 流控：`GLOBAL_API_RATE_LIMIT*`、`GLOBAL_WEB_RATE_LIMIT*`、`CRITICAL_RATE_LIMIT*`、`SEARCH_RATE_LIMIT*`
- 其他：`TLS_INSECURE_SKIP_VERIFY`、`TRUSTED_PROXIES`、`GEMINI_SAFETY_SETTING`、`COHERE_SAFETY_SETTING`、`TRUSTED_REDIRECT_DOMAINS`、`ENABLE_PPROF`、`PYROSCOPE_*`、`STREAMING_TIMEOUT`、`UPDATE_TASK`、`GENERATE_DEFAULT_TOKEN`、`ERROR_LOG_ENABLED`、`TASK_QUERY_LIMIT`、`TASK_TIMEOUT_MINUTES`、`DIFY_DEBUG`、`GET_MEDIA_TOKEN`、`GET_MEDIA_TOKEN_NOT_STREAM`、`USER_SESSION_*`、`LINUX_DO_*`

**5. 设计约束与约定**
- 所有可热更新的配置必须通过 `config.GlobalConfig.Register` 注册后才能被 `LoadFromDB` 识别；未注册的 key 回退到传统 `OptionMap` switch-case 处理。
- 复杂类型（struct/map/slice）统一以 JSON 字符串形式存储于数据库，字段使用 `json` tag 作为映射键。
- 敏感信息（如 `SESSION_SECRET`、`CRYPTO_SECRET`、各类支付密钥）仅通过环境变量注入，不进入 `OptionMap` 导出。
- 数据库为唯一持久化源，`common.OptionMap` 与 `config.GlobalConfig` 均为内存镜像，重启后从 DB 重新加载。
- 配置同步周期由 `SYNC_FREQUENCY` 控制，默认 60 秒；批量更新可通过 `BATCH_UPDATE_ENABLED=true` 开启。
