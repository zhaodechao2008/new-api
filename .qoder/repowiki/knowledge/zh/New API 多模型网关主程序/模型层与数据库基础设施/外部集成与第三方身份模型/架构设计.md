本模块位于 model 包内，全部以 GORM 结构体 + 函数式方法的形式暴露数据库访问能力，依赖全局 DB 实例（由上层初始化）。
- custom_oauth_provider.go：CustomOAuthProvider 结构体通过 gorm tag 映射到 custom_oauth_providers 表，内置 accessPolicyPayload 支持基于 JSONPath (gjson) 的字段映射与条件访问策略校验；提供 Get/Create/Update/Delete/IsSlugTaken 等函数式 API，并在删除时级联清理 UserOAuthBinding。
- external_identity_claim.go：ExternalIdentityClaim 通过复合唯一索引 (provider, subject) 和 (provider, user_id) 保证幂等归属，ClaimExternalIdentityWithTx 使用 clause.OnConflict{DoNothing: true} 实现原子 claim，并通过二次读取确认结果，避免跨数据库 RowsAffected 语义差异；同时提供 Release 与 InitializeExternalIdentityClaims 迁移旧 Telegram 绑定。
- midjourney.go：Midjourney 记录 AI 绘图任务状态，提供按用户/全量分页查询、HasUnfinishedMidjourneyTasks 存在性检查、UpdateWithStatus 基于 fromStatus 的 CAS 更新以及批量更新接口。
- vendor_meta.go：Vendor 作为供应商元数据表，采用软删除 + 联合唯一索引 uk_vendor_name_delete_at 保证名称唯一性，提供 Insert/Update/Delete/SearchVendors 等标准 CRUD。
依赖方向：仅依赖 common 工具（JSON 反序列化、时间戳）与 gorm.io/gorm，不反向依赖上层业务逻辑。
