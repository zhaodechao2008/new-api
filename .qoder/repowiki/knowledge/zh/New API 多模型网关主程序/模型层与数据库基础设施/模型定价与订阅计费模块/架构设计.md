本模块由两个相互独立但共享 `model` 包全局状态的核心子系统组成：
- 定价子系统（pricing.go / pricing_default.go / pricing_refresh.go）：以 `Pricing` 结构体为核心，通过 `GetPricing()` 暴露带 1 分钟惰性刷新与双检锁保护的只读缓存；`updatePricing()` 一次性从 `Ability/Model/Vendor` 表加载元数据，结合 `ratio_setting` 与 `billing_setting` 计算比率与计费表达式，并构建 `supportedEndpointMap` 与 `modelSupportEndpointTypes` 等并发安全映射；默认供应商映射由 `pricing_default.go` 中的 `defaultVendorRules` 与 `defaultVendorIcons` 驱动；强制刷新入口为 `RefreshPricing()`。
- 订阅子系统（subscription.go）：定义 `SubscriptionPlan`、`SubscriptionOrder`、`UserSubscription` 三个实体及其 GORM 钩子，使用 `cachex.HybridCache`（内存 LRU + Redis）两级缓存套餐与套餐信息，TTL 与容量通过环境变量 `SUBSCRIPTION_PLAN_CACHE_TTL`、`SUBSCRIPTION_PLAN_INFO_CACHE_TTL`、`SUBSCRIPTION_PLAN_CACHE_CAP`、`SUBSCRIPTION_PLAN_INFO_CACHE_CAP` 配置；核心流程包括 `CompleteSubscriptionOrder`（幂等完成支付）、`PurchaseSubscriptionWithBalance`（余额购买）、`AdminBindSubscription`（管理员绑定），并通过 `CreateUserSubscriptionFromPlanTx` 统一创建订阅快照，自动处理分组升级/回退、钱包溢出策略与配额重置周期计算。
- 并发与锁约定：定价更新遵循 `updatePricingLock -> channelSyncLock` 的严格顺序，避免与渠道缓存更新死锁；订阅操作普遍使用 `lockForUpdate` 行级锁与 `DB.Transaction` 事务保证一致性。
- 测试文件覆盖端点类型推导、高级自定义路由、订阅组变更对认证版本与会话的影响，以及按套餐/用户的配额重置逻辑。
