模块以 `main.go` 的 `SetRouter` 为唯一入口，按顺序调用 `SetApiRouter`、`SetDashboardRouter`、`SetRelayRouter`、`SetVideoRouter`、`SetAssetRouter`、`SetWebRouter` 将各功能域挂载到同一个 `*gin.Engine` 上。
- 每个子路由文件（`api-router.go`、`relay-router.go`、`video-router.go`、`asset-router.go`、`authz-router.go`、`web-router.go`、`dashboard.go`）定义一个独立的 `SetXxxRouter` 函数，通过 `router.Group` 划分命名空间并串联中间件。
- 鉴权由 `middleware` 包提供：`UserAuth`、`AdminAuth`、`RootAuth`、`TokenAuth`、`TokenOrUserAuth`、`TokenAuthReadOnly` 等按资源粒度组合使用；`RouteTag` 中间件给每条路由打上 `api`/`relay`/`web`/`old_api` 等标签用于统计。
- 公共能力通过 gzip、CORS、全局/模型级速率限制、BodyStorageCleanup、StatsMiddleware、Distribute 等中间件统一注入。
- Web 前端通过 `embed.FS` 内嵌 `web/dist` 静态资源，`NoRoute` 兜底返回 SPA index 或重定向到 `FRONTEND_BASE_URL`（主节点忽略该环境变量）。
- 路由注册采用“分组 + 闭包”模式：先 `Group` 再在 `{}` 块内声明具体路径，便于按权限/功能进一步嵌套子组（如 `/user/self`、`/subscription/admin`）。
- `channel_router_test.go` 和 `retired_frontend_routes_test.go` 通过反射遍历 `engine.Routes()` 断言权限映射与废弃路由是否移除，保证路由表与权限策略一致。
