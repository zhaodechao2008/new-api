模块以 `file_service.go` 为核心入口，通过 `types.FileSource` 接口抽象多种数据源（`URLSource`、`Base64Source`），由 `LoadFileSource` 统一调度：先查请求级 context 缓存，再双重检查加锁，最后按来源类型分发到 `loadFromURL` / `loadFromBase64`，结果写入 `types.CachedFileData` 并注册到 gin.Context 以便 `CleanupFileSources` 在请求结束时统一释放。
- `download.go` 封装 HTTP 下载逻辑，支持两种模式：启用 Worker 时通过 `DoWorkerRequest` 转发至远端 Worker，否则走本地 `GetSSRFProtectedHTTPClient()` 并做 SSRF 校验。
- `file_decoder.go` 提供 `GetFileTypeFromUrl` 和 `GetMimeTypeByExtension`，实现基于 Content-Type、Content-Disposition、URL 扩展名、`http.DetectContentType` 及 HEIF/HEIC 魔数探测的多层 MIME 推断。
- `image.go` 专注图片解码，通过 `getImageConfig` 依次尝试标准库 image、webp、HEIF/HEIC（ISOBMFF ispe box 解析）获取宽高配置。
- `audio.go` 仅做轻量 PCM16/G711 时长估算与 Base64 清理。
依赖方向单向：各子文件均依赖 `common`、`constant`、`types`、`logger` 和 `system_setting`，不反向被它们引用；`file_service.go` 是对外唯一聚合入口。
