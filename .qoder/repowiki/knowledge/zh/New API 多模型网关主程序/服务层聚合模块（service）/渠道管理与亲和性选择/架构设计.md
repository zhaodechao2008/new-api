本模块位于 service 包内，围绕渠道生命周期与请求路由策略组织为四个职责清晰的子文件：
- channel.go：渠道状态管理，提供 DisableChannel / EnableChannel / ShouldDisableChannel / ShouldEnableChannel 等函数，通过 model.UpdateChannelStatus 持久化状态并调用 NotifyRootUser 发送通知。
- channel_select.go：渠道选择核心，定义 RetryParam 结构体并在 CacheGetRandomSatisfiedChannel 中实现“auto”分组的跨组重试逻辑，使用 gin.Context 中的 ContextKeyAutoGroupIndex / ContextKeyAutoGroupRetryIndex 跟踪当前分组与重试进度，最终委托 model.GetRandomSatisfiedChannel 完成具体查询。
- channel_affinity.go：渠道亲和性子系统，基于 operation_setting.ChannelAffinityRule 对请求进行规则匹配（model/path/userAgent/value 正则），从 context_int / request_header / gjson 等多种 KeySource 提取亲和值，通过 cachex.HybridCache[int]（内存 LRU + Redis）缓存 channelID，并提供参数模板合并 ApplyChannelAffinityOverrideTemplate、使用统计 ObserveChannelAffinityUsageCacheByRelayFormat 及 AdminInfo 注入。
- codex_channel_models.go 与 codex_models.go：Codex 专用通道支持，FetchCodexChannelModels 负责 OAuth 认证、客户端版本缓存（codexClientVersionCache）、模型列表获取与凭据自动刷新 RefreshCodexChannelCredential，并通过 ratio_setting.WithCompactModelSuffix 生成变体模型名。
依赖方向单向向下：本模块依赖 common、model、dto、types、setting/operation_setting、constant、pkg/cachex、gin-gonic/gin，不反向被这些包依赖，属于服务层工具集合。
