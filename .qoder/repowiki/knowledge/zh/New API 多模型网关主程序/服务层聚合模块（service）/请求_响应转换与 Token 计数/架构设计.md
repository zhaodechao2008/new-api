本模块是 service 层中面向协议适配与用量计数的薄封装层，核心依赖 `service/relayconvert` 包完成实际的数据结构转换：
- `convert.go` 与 `request_converter.go` 将 `NormalizeCacheCreationSplit`、`StreamResponseOpenAI2Claude`、`ResponseOpenAI2Claude`、`ResponseOpenAI2Gemini`、`ConvertRequest`、`ClaudeToOpenAIRequest`、`GeminiToOpenAIRequest` 等调用转发给 `relayconvert`，并在 `init()` 中通过 `SetMediaResolver` 注入 Base64 媒体解析回调。
- `openai_chat_responses_compat.go` 与 `openai_chat_responses_mode.go` 提供 Chat Completions ↔ OpenAI Responses 的双向转换及策略判断（`ShouldChatCompletionsUseResponsesPolicy` / `ShouldChatCompletionsUseResponsesGlobal`），同样委托 `relayconvert` 实现。
- Token 计数分为两条路径：`tokenizer.go` 使用 `tiktoken-go/tokenizer` 为 OpenAI 文本模型提供精确编码；`token_estimator.go` 基于字符分类（CJK/Emoji/数学符号/URL分隔符等）与厂商权重表做快速估算；`token_counter.go` 作为统一入口，根据 `constant.CountToken`、`constant.GetMediaToken`、`constant.GetMediaTokenNotStream` 等开关选择是否计算、对图片按 patch/tile 模型分别计费、对音频按时长换算，并通过 `CountTextToken` 在 OpenAI 与非 OpenAI 模型间切换精确/估算路径。
- 依赖方向单向向外：本模块仅依赖 `dto`、`types`、`relay/common`、`relay/constant`、`setting/model_setting` 与第三方 `tiktoken-go`，不反向被 `relayconvert` 依赖，形成清晰的适配器边界。
