- 每个 Handler 函数均以 `info.InitChannelMeta(c)` 开头，随后对 `info.Request` 进行类型断言并 `common.DeepCopy` 后再处理。
- 请求体构建统一走 `relaycommon.NewOutboundJSONBody` 包装 `io.Reader`，并通过 `info.UpstreamRequestBodySize` 记录大小用于计费。
- 错误返回统一使用 `types.NewError` / `types.NewErrorWithStatusCode` / `types.NewOpenAIError`，并在非 200 时调用 `service.RelayErrorHandler` 后再用 `service.ResetStatusCode` 重置状态码。
- 参数覆盖逻辑统一在 JSON 序列化后调用 `relaycommon.ApplyParamOverrideWithRelayInfo(jsonData, info)`，失败时通过 `newAPIErrorFromParamOverride` 包装错误。
- 系统提示注入遵循相同模式：检查是否已存在 system 消息，不存在则前置插入，存在且允许覆盖时拼接内容并设置 `constant.ContextKeySystemPromptOverride` 上下文标记。
- 计费分支根据 Usage 中的 AudioTokens 或 TotalTokens 判断调用 `PostAudioConsumeQuota` 或 `PostTextConsumeQuota`，体现文本/音频双轨计费约定。
