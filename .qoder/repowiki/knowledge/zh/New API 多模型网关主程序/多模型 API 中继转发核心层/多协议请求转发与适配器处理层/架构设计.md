本模块以每个 `*Helper` 函数（如 `TextHelper`、`ClaudeHelper`、`GeminiHelper`、`AudioHelper`、`ImageHelper`、`EmbeddingHelper`、`RerankHelper`、`ResponsesHelper`、`WssHelper`）为单一入口，遵循统一的请求处理流水线：
- 通过 `info.InitChannelMeta(c)` 初始化渠道元信息；
- 从 `info.Request` 强转为具体 DTO（如 `dto.GeneralOpenAIRequest`、`dto.ClaudeRequest`、`dto.GeminiChatRequest` 等），并用 `common.DeepCopy` 深拷贝；
- 调用 `helper.ModelMappedHelper` 执行模型映射；
- 通过 `GetAdaptor(info.ApiType)` 获取对应渠道适配器并 `Init(info)`；
- 根据全局/渠道的 `PassThroughRequestEnabled` 或 `PassThroughBodyEnabled` 决定透传原始 Body 还是经 `adaptor.Convert*Request` 转换后 JSON 序列化；
- 使用 `relaycommon.RemoveDisabledFields` 移除禁用字段、`ApplyParamOverrideWithRelayInfo` 应用参数覆盖；
- 调用 `adaptor.DoRequest` 发起上游请求，`service.RelayErrorHandler` + `service.ResetStatusCode` 处理非 200 状态码；
- 调用 `adaptor.DoResponse` 解析响应，最终通过 `service.PostTextConsumeQuota` / `PostAudioConsumeQuota` / `PostWssConsumeQuota` 计费。

特殊路径：`chat_completions_via_responses.go` 提供 `chatCompletionsViaResponses` 将 Chat Completions 请求经 `service.ConvertRequestVia` 转换为 OpenAI Responses 再转发；`mjproxy_handler.go` 独立实现 Midjourney 代理（任务提交、轮询、图片直链、通知回调），不走 Adaptor 模式；`websocket.go` 基于 gorilla/websocket 建立双向连接并通过 `TargetWs` 透传。依赖方向单向指向 `relay/common`、`relay/helper`、`service`、`setting/model_setting`、`types`，不反向依赖上层路由。
